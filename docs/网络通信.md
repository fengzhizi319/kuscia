# Kuscia 网络通信

## 1. 概述

Kuscia 是一个基于 Kubernetes/K3s 的安全协作基础设施框架。节点之间所有跨域通信都通过 **Kuscia Gateway（Envoy）** 统一进出，域内服务通过 **CoreDNS** 发现，数据访问通过 **DataMesh** 完成，BFIA 互联互通消息通过 **Transport** 传递。

本文档从源码实现出发，系统梳理 Kuscia 网络通信的架构、数据流、关键组件、TLS/mTLS、DomainRoute/ClusterDomainRoute、DataMesh、DataProxy、Transport 以及相关的 gRPC/HTTP 接口和 Proto 定义。

## 2. 运行模式与网络模块

Kuscia 的启动入口为 `cmd/kuscia/start/start.go`。同一个二进制根据 `kuscia.yaml` 中的 `mode` 字段启动不同模块集合：

| 运行模式 | 说明 | 启动的典型网络模块 |
|---|---|---|
| `master` | 中心化控制节点 | k3s、envoy、domainroute、reporter、kusciaapi、coredns |
| `lite` | 轻量数据节点 | agent、envoy、datamesh、transport、domainroute、kusciaapi、coredns |
| `autonomy` | 自治节点（控制+数据） | 全部模块 |

模块注册代码（`cmd/kuscia/start/start.go`）：


## 4. 网络架构

### 4.1 控制平面与数据平面

- **控制平面**：K3s、CRD（DomainRoute、ClusterDomainRoute、DomainData 等）、DomainRoute Controller、Scheduler、InterConn Controller。
- **数据平面**：App Pod、Envoy Gateway、DataMesh、Transport、CoreDNS、Agent。

### 4.2 域名约定与服务发现

Kuscia 内部使用 `*.svc` 风格的域名寻址：

- 同域服务：`datamesh.alice.svc`、`kusciaapi.alice.svc`、`gateway.alice.svc`
- 跨域服务：`*.bob.svc`

**CoreDNS 插件（`pkg/coredns`）** 负责解析：

- 本域（namespace 匹配）的服务名：从缓存返回实际后端 IP。
- 其他域的服务名：统一返回 `EnvoyIP`，把流量引入本节点 Envoy 的 internal listener（80 端口）。

核心逻辑在 `pkg/coredns/kuscia.go`：

```go
func (e *KusciaCoreDNS) Records(ctx context.Context, state request.Request, exact bool) ([]msg.Service, error) {
    name := state.Name()
    name = name[:len(name)-1]

    if strings.HasSuffix(name, ".svc") {
        fields := strings.Split(name, ".")
        n := len(fields)
        if fields[n-2] == e.Namespace {
            item, found = e.Cache.Get(strings.TrimSuffix(name, ".svc"))
        } else {
            item = []string{e.EnvoyIP}
            found = true
        }
    }
    // ...
    services := []msg.Service{{Host: endpoints[counter%uint64(len(endpoints))], TTL: defaultTTL}}
}
```

`etc/conf/corefile` 示例：

```text
.:53 {
    kuscia {
        fallthrough
    }
    template IN NS . refuse
    forward . /home/kuscia/var/tmp/resolv.conf
}
```

## 6. DomainRoute 与 ClusterDomainRoute

### 6.1 概念

- **DomainRoute（DR）**：命名空间级资源，定义源域到目标域的路由、认证、加密规则。
- **ClusterDomainRoute（CDR）**：集群级资源，主要在中心化组网中由 Master 统一配置 Lite 节点之间的路由；DomainRouteController 会据此在各 Lite 节点对应的命名空间下自动创建 DR。

CRD 定义位于 `pkg/crd/apis/kuscia/v1alpha1/domainroute_types.go`。

### 6.2 核心字段

```yaml
spec:
  source: alice
  destination: bob
  interConnProtocol: kuscia    # kuscia / bfia
  endpoint:
    host: 172.2.0.2
    ports:
      - name: http
        protocol: HTTP        # HTTP / GRPC
        isTLS: true
        port: 1080
  authenticationType: Token    # Token / MTLS / None
  tokenConfig:
    tokenGenMethod: RSA-GEN
    rollingUpdatePeriod: 0
  mTLSConfig:
    tlsCA: BASE64<CA>
    sourceClientCert: BASE64<cert>
    sourceClientPrivateKey: BASE64<key>
  transit:
    transitMethod: THIRD-DOMAIN   # THIRD-DOMAIN / REVERSE-TUNNEL
    domain:
      domainID: joke
  bodyEncryption:
    algorithm: AES
  requestHeadersToAdd:
    Authorization: Bearer xxx
```

### 6.3 认证方式

#### Token（RSA-GEN）

- 默认方式，主要用于中心化组网。
- 源端生成 16 字节随机数，用目标端公钥加密后发送到对端 `/handshake`。
- 目标端生成另外 16 字节，用源端公钥加密返回。
- 两端各自拼接成 32 字节通信 Token，并写入 DomainRoute 的 `status.tokenStatus`。

Handshake Server 监听 `0.0.0.0:1054`，路径定义在 `proto/api/v1alpha1/handshake/handshake.proto`：

```protobuf
message HandShakeRequest {
    string domain_id = 1;
    string type = 2;
    TokenConfig token_config = 3;
    int64 request_time = 4;
}

message HandShakeResponse {
    Status status = 1;
    Token token = 2;
}

message RegisterRequest{
    string domain_id=1;
    string csr=2;
    int64 request_time=3;
}

message RegisterResponse {
    Status status = 1;
    string cert = 3;
    string master_pubkey = 4;
}
```

路径：

- `/handshake`：所有节点
- `/register`：仅 Master 节点

#### MTLS

- 源端配置 `mTLSConfig.sourceClientCert` / `sourceClientPrivateKey` / `tlsCA`。
- DomainRouteController 在生成上游 Envoy Cluster 时附加 `TransportSocket`，开启双向 TLS。
- 目标端 external listener 使用 `kuscia_token_auth` 或 TLS 校验客户端证书。

TLS 配置生成函数在 `pkg/gateway/xds/tls_config.go`：

```go
func GenerateUpstreamTLSConfigByCertStr(cert, key, ca []byte) (*core.TransportSocket, error)
func GenerateDownstreamTLSConfigByCertStr(cert, key, ca []byte) (*core.TransportSocket, error)
```

### 6.4 转发模式

- **直连**：`transit` 为空，流量从源网关直接发到目标网关。
- **THIRD-DOMAIN（节点转发）**：流量先发到中转域，再由中转域转发到目标域。适用于无法直连的场景。
- **REVERSE-TUNNEL（反向隧道）**：目标侧网关主动向源侧网关建立长连接，源侧请求通过该连接转发到目标侧。适用于目标侧不便于暴露监听端口的场景。

### 6.5 Body 加密

- 当 `bodyEncryption.algorithm: AES` 启用时，源端 Envoy 使用 `kuscia_crypt` 加密请求体，目标端 Envoy 解密。
- 加密密钥派生自 Token，因此仅 Token 认证方式支持。

### 6.6 DomainRouteController 如何生成 Envoy 规则

`pkg/gateway/controller/domain_route.go` 核心逻辑：

1. 监听 DomainRoute 事件，加入工作队列。
2. 对源端是本域的 DR：
   - `addClusterWithEnvoy()` 生成指向目标网关的上游 Cluster，附加 mTLS transport socket。
   - `updateEnvoyRule()` 在 `internal-route` 中添加 VirtualHost（`*.bob.svc`），并写入 Token。
   - 如有 Body 加密，调用 `updateEncryptRule()` 配置 `kuscia_crypt`。
3. 对目标端是本域的 DR：
   - 将源端 Token 写入 `kuscia_token_auth` 的 source tokens，用于 external listener 鉴权。
   - 如有 Body 加密，配置解密规则。
   - 处理 `requestHeadersToAdd`（如添加 `Authorization`）。

## 7. TLS / mTLS

### 7.1 证书体系

每个 Kuscia 节点拥有一套证书：

- CA 证书/私钥：`ca.crt` / `ca.key`
- Domain 证书/私钥：`domain.crt` / `domain.key`
- 各服务端证书：`kusciaapi-server.crt/key`、DataMesh 服务器证书等

### 7.2 Envoy TLS 配置生成

`pkg/gateway/xds/tls_config.go`：

```go
func generateUpstreamTLSConfig(cert, key, ca []byte) (*core.TransportSocket, error) {
    tlsContext := &tls.UpstreamTlsContext{
        CommonTlsContext: &tls.CommonTlsContext{},
    }
    if len(cert) != 0 {
        tlsContext.CommonTlsContext.TlsCertificates = []*tls.TlsCertificate{{
            CertificateChain: &core.DataSource{Specifier: &core.DataSource_InlineString{InlineString: string(cert)}},
            PrivateKey:       &core.DataSource{Specifier: &core.DataSource_InlineString{InlineString: string(key)}},
        }}
    }
    if len(ca) != 0 {
        tlsContext.CommonTlsContext.ValidationContextType = &tls.CommonTlsContext_ValidationContext{
            ValidationContext: &tls.CertificateValidationContext{
                TrustedCa: &core.DataSource{Specifier: &core.DataSource_InlineString{InlineString: string(ca)}},
            },
        }
    }
    // ...
}

func generateDownstreamTLSConfig(cert, key, ca []byte) (*core.TransportSocket, error) {
    tlsContext := &tls.DownstreamTlsContext{
        CommonTlsContext: &tls.CommonTlsContext{
            TlsCertificates: []*tls.TlsCertificate{{...}},
        },
    }
    if len(ca) != 0 {
        tlsContext.RequireClientCertificate = &wrappers.BoolValue{Value: true}
        tlsContext.CommonTlsContext.ValidationContextType = ...
    }
    // ...
}
```

- 上游（Source -> Destination）：使用 `UpstreamTlsContext`，携带客户端证书，校验服务端 CA。
- 下游（Destination Gateway）：使用 `DownstreamTlsContext`；当传入 CA 时，设置 `RequireClientCertificate: true`，开启 mTLS。

## 8. DataMesh

### 8.1 作用

DataMesh 是 Kuscia 的统一数据访问层，基于 **Apache Arrow Flight** 协议，为上层应用（如 SecretFlow）提供跨数据源的数据读写能力。它负责：

- 数据源和数据集（DomainData、DomainDataSource、DomainDataGrant）的元数据管理。
- 通过 Arrow Flight gRPC 提供数据读写接口。
- 根据数据源类型路由到内置 IO 或外部 DataProxy。

### 8.2 启动与端口

`cmd/kuscia/modules/datamesh.go`：


### 8.3 gRPC 服务注册

`pkg/datamesh/bean/grpc_server_bean.go`：

```go
func (s *grpcServerBean) Start(ctx context.Context, e framework.ConfBeanRegistry) error {
    opts := []grpc.ServerOption{
        grpc.ConnectionTimeout(time.Duration(s.config.ConnectTimeOut) * time.Second),
        grpc.ChainUnaryInterceptor(interceptor.UnaryRecoverInterceptor(...)),
        grpc.StreamInterceptor(interceptor.StreamRecoverInterceptor(...)),
        grpc.MaxRecvMsgSize(256 * 1024 * 1024),
    }
    if !s.config.DisableTLS {
        serverTLSConfig, err := tls.BuildServerTLSConfig(s.config.TLS.RootCA,
            s.config.TLS.ServerCert, s.config.TLS.ServerKey)
        creds := credentials.NewTLS(serverTLSConfig)
        opts = append(opts, grpc.Creds(creds))
    }

    addr := fmt.Sprintf("%s:%d", s.config.ListenAddr, s.config.GRPCPort)
    lis, err := net.Listen("tcp", addr)
    server := grpc.NewServer(opts...)

    domainDataService := service.NewDomainDataService(s.config)
    datasourceService := service.NewDomainDataSourceService(s.config, s.cmConfigService)
    datamesh.RegisterDomainDataServiceServer(server, grpchandler.NewDomainDataHandler(domainDataService))
    datamesh.RegisterDomainDataSourceServiceServer(server, grpchandler.NewDomainDataSourceHandler(datasourceService))
    datamesh.RegisterDomainDataGrantServiceServer(server, grpchandler.NewDomainDataGrantHandler(service.NewDomainDataGrantService(s.config)))

    flight.RegisterFlightServiceServer(server, handler.NewDataMeshFlightHandler(domainDataService, datasourceService, s.config.DataProxyList))

    reflection.Register(server)
    return server.Serve(lis)
}
```

### 8.5 Arrow Flight 数据流

## 9. DataProxy（数据代理）

### 9.1 作用

DataProxy 用于扩展 Kuscia 的数据源访问能力。Kuscia 内置 IO 无法覆盖的数据源（如 ODPS、Hive、Kingbase、Dameng 等）可通过 DataProxy 代理访问。

DataProxy 采用 Java 实现，基于 Apache Arrow Flight 协议与 DataMesh 交互。

### 9.2 配置

在 `kuscia.yaml` 中配置 `dataMesh.dataProxyList`：

### 10.3 HTTP 端点

`pkg/transport/server/http/server.go` 监听 `127.0.0.1:8081`：

```go
func (s *Server) Start(ctx context.Context) error {
    mux := http.NewServeMux()
    mux.HandleFunc("/v1/interconn/chan/transport", s.generateHandler(invoke))
    mux.HandleFunc("/v1/interconn/chan/invoke",  s.generateHandler(invoke))
    mux.HandleFunc("/v1/interconn/chan/pop",     s.generateHandler(pop))
    mux.HandleFunc("/v1/interconn/chan/peek",    s.generateHandler(peek))
    mux.HandleFunc("/v1/interconn/chan/release", s.generateHandler(release))

    sr := &http.Server{
        Addr:           fmt.Sprintf("127.0.0.1:%d", s.svrConfig.Port),
        Handler:        mux,
        ReadTimeout:    time.Duration(s.svrConfig.ReadTimeout) * time.Second,
        WriteTimeout:   time.Duration(s.svrConfig.WriteTimeout) * time.Second,
        IdleTimeout:    time.Duration(s.svrConfig.IdleTimeout) * time.Second,
        MaxHeaderBytes: 1 << 20,
    }
    // ...
}
```

核心语义：

| 操作 | 说明 |
|---|---|
| invoke/transport/push | 向某 session + topic 推送消息 |
| pop | 阻塞取出消息 |
| peek | 查看但不取出 |
| release | 释放 topic 或 session |

### 10.4 gRPC 服务

`pkg/transport/server/grpc/server.go` 监听 `0.0.0.0:9091`，注册：

```go
pb.RegisterPrivateTransferProtocolServer(gs, s)
pb.RegisterPrivateTransferTransportServer(gs, s)
```

- `PrivateTransferProtocol`
  - `rpc transport (stream Inbound) returns (stream Outbound)`
  - `rpc invoke (Inbound) returns (Outbound)`
- `PrivateTransferTransport`
  - `rpc peek (PeekInbound) returns (TransportOutbound)`
  - `rpc pop (PopInbound) returns (TransportOutbound)`
  - `rpc push (PushInbound) returns (TransportOutbound)`
  - `rpc release (ReleaseInbound) returns (TransportOutbound)`

## 12. 跨域通信数据流示例

### 12.1 alice Pod -> bob Pod

1. alice 的算法 Pod 发起请求到 `service.bob.svc`。
2. Pod DNS 查询打到本域 CoreDNS，因 namespace 不是 `alice`，CoreDNS 返回 EnvoyIP。
3. 流量进入 alice Envoy 的 **internal-listener（80）**。
4. `internal-route` 中匹配 `*.bob.svc` 的 VirtualHost，该 VirtualHost 由 DomainRouteController 根据 `alice -> bob` 的 DomainRoute 动态生成。
5. 请求被路由到 upstream cluster `alice-to-bob-http`，指向 bob 网关的 `endpoint.host:endpoint.port`（默认 1080）。
6. 若开启 Token，请求头携带 `Kuscia-Token`；若开启 mTLS，建立双向 TLS。
7. 若开启 BodyEncryption，`kuscia_crypt` 在发送前加密请求体。
8. 请求到达 bob Envoy 的 **external-listener（1080）**。
9. `kuscia_token_auth` 校验 Token；`kuscia_gress` 根据 `Kuscia-Host` 头重写目标地址，转发到 internal-listener。
10. internal-listener 根据 `:authority` 将请求转发到 bob 域内对应 Pod/Service。

### 12.2 alice 应用 -> bob DataMesh

1. alice 应用通过 Arrow Flight 客户端访问 `datamesh.bob.svc:8071`。
2. 经 CoreDNS 解析到 alice EnvoyIP，走 internal-listener。
3. DomainRoute 将流量路由到 bob 网关 external-listener。
4. bob Envoy 根据 `Kuscia-Host` 转发到本域 `datamesh.bob.svc`（host IP 8071）。
5. bob DataMesh 处理请求，返回 FlightInfo，后续 DoGet/DoPut 数据流类似。

### 12.3 BFIA PTP 跨域消息

1. alice Transport 将消息推送到 `transport.bob.svc`。
2. 经 CoreDNS/Envoy 路由到 bob Transport。
3. bob Transport 按 `session-id` + `topic` 存入内存队列。
4. bob 算法 Pod 通过 pop/peek 取出消息。

## 15. 故障排查

### 15.1 常用检查命令

```bash
# 查看 Envoy 配置
kubectl exec -it <kuscia-pod> -- curl http://127.0.0.1:10000/config_dump

# 查看 Envoy 就绪状态
kubectl exec -it <kuscia-pod> -- curl http://127.0.0.1:10000/ready

# 查看 DomainRoute 状态
kubectl get domainroute -n <ns> -o yaml
kubectl get clusterdomainroute -o yaml

# 查看日志
tail -f /home/kuscia/var/logs/domainroute/domainroute.log
tail -f /home/kuscia/var/logs/envoy/envoy.log
tail -f /home/kuscia/var/logs/datamesh/datamesh.log
```

### 15.2 Envoy 日志与 traceid

Envoy 通过 `x-b3-traceid` 标识请求。日志格式：

```
<src_ip> - [<time>] <namespace> <service_name> "<method> <path> <protocol>" <traceid> <spanid> <status> <req_bytes> <resp_bytes> ...
```

- `external.log`：入口流量。
- `internal.log`：出口流量。
- 转发场景（Alice -> Bob -> Carol）下，中间节点 Bob 的 external 和 internal 日志都会出现同一 traceid。

### 15.3 常见问题

| 现象 | 可能原因 | 排查方法 |
|---|---|---|
| Token 未就绪 | handshake server 1054 不可达 | 检查网络连通性、DomainRoute 状态 |
| mTLS 握手失败 | 证书链、CA、SAN 不匹配 | `openssl s_client -connect <peer>:1080 ...` |
| 路由未生成 | DomainRouteController 未正常运行 | 查看 domainroute 日志、CRD 状态 |
| DNS 解析异常 | CoreDNS 未就绪 | 检查 `/etc/resolv.conf`、CoreDNS 日志 |
| DataProxy 无法访问 | `dataProxyList` 未配置 | 检查 `kuscia.yaml`、DataMesh 日志 |
| 跨域请求 403 | Token 鉴权失败 | 检查 `status.tokenStatus`、Envoy token_auth 配置 |
